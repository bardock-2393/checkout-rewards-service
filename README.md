# Checkout & Rewards Service

Backend for an ecommerce store: carts, checkout, inventory, and an nth-order
discount coupon system. In-memory storage, no database. Built with
FastAPI/Python.

Time spent: ~5 hours.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Run

```bash
uvicorn app.main:app --reload
```

Interactive API docs (auto-generated by FastAPI): http://127.0.0.1:8000/docs

Coupon config (`n` = every nth order, `x` = percent off) is seeded in
`app/main.py::create_app` — defaults to `n=5, x=10`.

## Test

```bash
pytest -v
```

18 tests, including two concurrency tests run with real parallel async
requests (`asyncio.gather` over an `httpx.AsyncClient`), not just sequential
happy paths:

- `test_concurrent_checkouts_never_oversell` — 5 carts race for a product
  with 3 units of stock; exactly 3 succeed.
- `test_concurrent_checkouts_only_one_redeems_the_coupon` — 6 carts race to
  redeem the same single-use coupon; exactly 1 succeeds.

## API

Seed catalog: 5 products (`p1`-`p5`), `p5` has limited stock (3 units) to
exercise the out-of-stock path.

| Method & Path | Description |
|---|---|
| `GET /products` | List catalog with live price/stock |
| `POST /carts` | Create a cart → `{cart_id}` |
| `GET /carts/{cart_id}` | View cart with live prices and computed totals |
| `POST /carts/{cart_id}/items` | Add item `{product_id, quantity}` |
| `PATCH /carts/{cart_id}/items/{product_id}` | Update quantity `{quantity}` |
| `DELETE /carts/{cart_id}/items/{product_id}` | Remove item |
| `POST /carts/{cart_id}/checkout` | Checkout, optional `{coupon_code}` → order. Idempotent: retrying after success returns the same order. |
| `GET /orders/{order_id}` | Retrieve an order |
| `POST /admin/coupons/generate` | Admin: issue a coupon if the next milestone has been reached |
| `GET /admin/report` | Admin: revenue/discount/coupon/order summary |

All money fields are integer paise (1 rupee = 100 paise) to avoid float
rounding errors.

### Error responses

Non-2xx responses from domain logic are `{"error": CODE, "message": "..."}`:

`VALIDATION_ERROR` (400) · `NOT_FOUND` (404) · `CART_ALREADY_CHECKED_OUT` (409)
· `OUT_OF_STOCK` (409) · `INVALID_COUPON` (400) · `COUPON_ALREADY_REDEEMED` (409)
· `MILESTONE_NOT_REACHED` (409)

Malformed request bodies (e.g. a non-positive `quantity`) are rejected by
FastAPI's own request validation and return the standard `422` shape instead.

### curl walkthrough

```bash
# create a cart and add items
CART=$(curl -s -X POST localhost:8000/carts | python3 -c "import sys,json;print(json.load(sys.stdin)['cart_id'])")
curl -s -X POST localhost:8000/carts/$CART/items -H 'content-type: application/json' -d '{"product_id":"p1","quantity":2}'

# checkout
curl -s -X POST localhost:8000/carts/$CART/checkout

# once 5 orders have been placed, an admin can issue a coupon
curl -s -X POST localhost:8000/admin/coupons/generate

# use the coupon code on a later checkout
curl -s -X POST localhost:8000/carts/$CART2/checkout -H 'content-type: application/json' -d '{"coupon_code":"ABCD1234"}'

# admin report
curl -s localhost:8000/admin/report
```

See `DECISIONS.md` for the design reasoning behind the idempotency,
concurrency, money, and coupon-milestone choices.
